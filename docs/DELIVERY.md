# 实施切片、验证与交付

状态：首期交付与验收要求。运行时、工程检查、真实库测试和部署工件已实现；逐项证据与未完成生产验收见 implementation/ACCEPTANCE.md。

## 1. 实施范围与责任

首期闭合 TypeScript SDK → Collector → PostgreSQL 高可用持久化 → Query API → CLI 的真实路径，覆盖浏览器和服务端错误、权限隔离、幂等、保留、审计和源码位置还原。生产 HA 目标与数据语义见 [架构](ARCHITECTURE.md)、[契约](SDK-AND-API.md)、[存储](BACKEND.md) 与 [运行](OPERATIONS.md)。

本项目不修改 Core 的账号、账务或执行状态，不改 OneAster 首页视觉，不直接接管现有业务部署。业务接入作为单独实施切片，在对应仓库复核 AGENTS、安装版本文档、脚本和既有改动后进行。没有推送、发布或部署指令时不执行这些外部动作。

应用服务负责权限、协议和有界处理；SDK 负责采集、清理和有限送达；数据库驱动负责确认、并发和结果一致性；部署负责人负责故障域、隔离、网络、秘密配置、备份和恢复。99.99% 的责任是整条链路，不能由某个库的单测代替。

## 3. 接口与业务行为验证矩阵

下列为验收要求；已执行入口、局部覆盖与未执行部分见 implementation/ACCEPTANCE.md，不把用例数量当质量证据。

| 编号 | 前置状态与动作 | 期望结果与机制 | 验证入口 |
| --- | --- | --- | --- |
| C01 | 同一事件在两个 Collector 并发发送 | 只存在一个逻辑事件，两次确认均经过同步屏障 | 真实 DB + 双进程 HTTP |
| C02 | 同身份不同载荷并发 | 一方明确冲突，不覆盖原事件，不泄露已存正文 | 真实 DB + HTTP |
| C03 | 整批含冲突或非法项 | PostgreSQL 事务整批回滚，客户端重组保持原 ID | HTTP + DB 查询 |
| C04 | COMMIT 已成功，HTTP 响应被切断 | 重试复用原时间与保留期，逻辑计数仍为一次 | TCP 故障代理 |
| C05 | 主库本地可见，但同步确认被阻断；再次发送相同事件 | 重复路径不能只读 ACK；无安全确认则结果未知 | 真实复制故障探针 |
| C06 | 阻断同步副本，设置短 statement_timeout，触发独立提交截止、主动取消、断连和晚到 COMMIT | 观察到 statement_timeout 不能限制 SyncRep；独立截止内停止确认，先锁定 unknown 再取消，晚到标签不触发 200 | 目标 PostgreSQL/pg 版本 |
| C07 | 单节点、主库或单可用区永久丢失 | 已确认 ID 在恢复后全部存在；记录实际 RTO | 真实三故障域演练 |
| C08 | 旧主与 etcd 失联、进程暂停或负载饥饿 | 旧主被隔离，不能与新主同时确认 | watchdog/fencing 装置 |
| C09 | 同步副本不足 | 明确失败，不异步降级；恢复后原 ID 可重试 | Patroni/复制故障装置 |
| C10 | 两项目/不同服务复用标识；error-only 凭证查询普通事件与错误，随后删除事件仅留收据 | 列表、详情、收据、游标、审计按服务与 allowedKinds 隔离；普通事件含到期状态始终 404，授权错误到期返回 410 | HTTP + RLS 真实库 |
| C11 | 浏览器伪造 server source，或读写凭证混用 | 拒绝越权，浏览器事件始终为不可信来源 | HTTP 契约 |
| C12 | 凭证撤销后用旧游标或重发原事件 | 当前权限优先，幂等和游标不绕过授权 | 配置热更新 + HTTP |
| C13 | 配置部分写入、版本回退或到期 | 不采用损坏/回退配置；到期 fail closed；暴露可诊断状态 | 多进程配置故障 |
| C14 | 查询读取后发生主库切换 | 不在新主补审计后返回旧结果；整次调用失败或重跑 | DB 连接故障代理 |
| C15 | 持续写入与迟提交期间分页，多条详情 SQL 之间跨过到期时刻 | 同次调用共享 REPEATABLE READ 快照和固定 as_of；新页重新确定 as_of；导出明确非跨页快照 | 并发 HTTP/SQL |
| C16 | 大查询、慢锁、连接池耗尽或大量单项目流量 | 限制等待/扫描/内存，明确背压，受保护资源可观测 | 混合负载 |
| C17 | 一个事件超限、批次超限、错误 getter 或循环对象 | 有界拒绝/裁剪，不阻塞业务，不递归采集自身错误 | SDK 公共入口 |
| C18 | 原事件到期但清理任务暂停 | as_of 已到期的新查询立即隐藏；已开始查询遵守固定 as_of；重复不续期、不复活 | 可控时钟 + 真实 DB |
| C19 | 在详情两次 SELECT 之间执行到期 DELETE、DROP/DETACH 分区，维护实例退出 | DELETE 不破坏读取快照；父表锁阻止分区中途消失，维护锁超时退出；无伪完整性错误，后续事务正确返回到期，任务可恢复 | 真实 DB + 多维护进程 |
| C20 | SDK 初始化两次、热更新、close、多帐号切换 | 监听/计时器/请求清理，不重复记录、不串用户 | Browser/Node 生命周期 |
| C21 | 服务端并发两个用户请求 | 传入上下文保持隔离，没有用户状态单例污染 | Node 并发入口 |
| C22 | 网络离线、无效 200、Beacon 入队与超时 | 只有可验证 ACK 被确认；有限重试和字节上限成立 | Playwright + HTTP 假体 |
| C23 | 崩溃、Promise 拒绝、React 渲染与已处理失败 | 相应入口有规范错误；预期控制流按分类处理 | Browser/Next 实际适配 |
| C24 | 错误含凭证、URL 查询、自由文本和敏感正文 | 默认安全投影，不在事件/拒绝日志/审计中泄漏原值 | 捕获服务出口与日志 |
| C25 | 构建 A/B 的相同文件名、不同映射与行列基准 | 只按匹配构建还原，拒绝目录逃逸与网络取图 | CLI 人工算例 |
| C26 | SQLite 或 windowed 驱动配置成 HA | 启动明确拒绝，不降级生产承诺 | 存储能力契约 |
| C27 | 迁移、逐区发布、旧 SDK 与新服务共存 | 扩展先行，兼容窗口可观测，工件与数据回退边界明确 | 部署装置 |
| C28 | 从备份和 WAL 在隔离区恢复 | 可校验收据、事件和配置，记录实际 RPO/RTO | 灾备还原装置 |
| C29 | 角色默认 client_min_messages=ERROR，池复用后设置被改动，或中间层屏蔽 notice | 驱动恢复并核验 warning 后才操作；无法保证通知可达时拒绝 HA；负向探针展示取消后仅有 COMMIT 不能视为安全确认 | 目标 PostgreSQL/pg 协议探针 |
| C30 | 持续制造未知提交，隔离清理连接，再重启或替换应用实例 | HTTP 截止不等待清理；遗留会话继续占物理节点预算，预算满后停止新准入；重启先盘点接管再开放预算，恢复后核对 pg_stat_activity | 真实 DB + 进程/网络故障 |

期望来自用户要求、协议不变量和人工样本，不用被测函数自己生成期望。涉及事务、唯一性、锁、RLS、复制或查询计划的保证必须用真实目标数据库；内存替身只用于网络/时间等可控边界。

## 4. 工程检查与工件

以下命令均由 package.json 定义，使用 `bun run` 执行：

| 脚本 | 职责 |
| --- | --- |
| lint | 依赖边界、类型感知 oxlint、bun fmt 格式检查；零错误与警告 |
| typecheck | 各包 TypeScript 与公共类型兼容检查 |
| build | browser/server SDK 与类型声明、Node 服务和 CLI 工件；确认浏览器依赖图无服务端代码 |
| test:unit | 规范化、授权、序列化、队列、计时和纯规则的行为用例与覆盖率 |
| test:integration | Node + PostgreSQL 18 的事务、RLS、保留、审计与查询；真实驱动 |
| test:e2e | SDK、HTTP、CLI、浏览器和实际 Next 适配的完整路径 |
| test:ha | 独立故障装置，复现确认、切换、隔离与三故障域验收 |

各包输出 ESM 与声明文件，SDK 的通用入口不自动导入框架或数据库。服务和 CLI 构建后在目标 Node Linux 镜像验收；本机可运行不替代目标镜像。CI 固定运行时、依赖锁、镜像摘要和协议样本版本，制品不含秘密、生产数据或公开可访问的 source map。

覆盖率范围与阈值由 vitest.config.ts 给出，优先保证确认、权限、并发和清理的关键分支均有行为断言。交付分别报告 statements、branches、functions、lines 及配置门禁结果；不得用局部数字声称全仓达标，也不为覆盖率添加复述实现的用例。

## 5. 发布、接入与迁移边界

平台无既有生产数据，首期不存在获准执行的存量迁移。迁移与维护通过独立角色在隔离测试环境验证，生产执行仍需对应部署授权。业务项目接入时只新增明确公共 SDK 入口、项目事件注册及错误边界，不修改其上游业务契约。

平台先以非关键样本服务验证，再接入真实业务；遥测失败不改变登录、充值和执行结果。SDK 不自动重试业务操作，重试只针对同一个遥测事件。正式接入之前实测额外延迟、bundle、任务清理和数据出口。

应用版本、数据库模式、项目配置和协议分别版本化，回滚条件分别记录。不得通过跳过测试、弱化断言、降低可靠性策略或静默更换驱动制造通过。

## 6. 独立审查与设计变更

完成机械文档检查后，对最终设计包进行一次独立只读审查，重点挑战确认/复制、权限、幂等、分页、保留、故障域和资源生命周期。审查者不修改文件；结论必须给出具体位置、触发条件和后果，区分确定问题与待验证假设。

主会话核对发现后修正文档、补足机制或明确限制。设计审查不等于运行验证，也不等于完成生产认证。实施每个高风险切片后，还需要基于实际代码和真实结果的审查。
