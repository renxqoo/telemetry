# SDK 边界缺陷修复记录

日期：2026-11-01 至 2026-11-02。范围为本轮审查确认的七项缺陷，采用逐项回归失败、最小修复、相关验证的 TDD 流程。

## 目标与实施顺序

| 缺陷                         | 目标行为                                                                                           | 验证入口                                                    |
| ---------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| Error 元数据变化后泄露消息   | 不读取、复制或解析原始 message/stack/cause，SDK 错误 frames 为空，保留安全错误标识与上下文         | SDK 公开 captureError、真实 Node 子进程、真实采集与查询链路 |
| 端点跨源或远程 HTTP 泄露数据 | 绝对端点只允许 HTTPS 或 loopback HTTP；浏览器相对端点按实际页面 origin 固定，不受 base 标签影响    | Browser/Server 构造、传输及真实浏览器 fetch/Beacon          |
| span 批次终止丢失冷却        | Retry-After 冷却保存在实例上，当前批次终止、后续入队及 flush/close 均不能提前发送                  | tracing 公开接口、受控时间与传输                            |
| 墙钟回拨突破等待截止         | 事件 SDK 的调度、重试预算、去重窗口、flush/close 使用单调时钟；墙钟只用于发生时间和 HTTP 日期换算  | SDK 公开生命周期、重试与去重                                |
| 关闭错误捕获同时关闭离页补发 | 所有浏览器实例均参与生命周期监听；全局错误仅交给同范围最近启用自动捕获的实例，离页补发交给最近实例 | EventTarget、Beacon、实例关闭与恢复                         |
| 未来版本接受多值 traceparent | 拒绝合并或数组形式的多值 traceparent，保留合法单值未来版本与独立 tracestate 处理                   | extractTraceContext 公开入口                                |
| 架构门禁遗漏实际依赖         | 从 workspace manifest 取得包名，识别具名、副作用、动态与 require 依赖，并检查实际包和相对路径边界  | 临时目录运行原架构检查入口                                  |

## 边界与风险

公共方法签名、HTTP/DTO、持久化和配置字段不变。用户在 2026-11-02 明确选择严格隐私：SDK 即时停止不可信文本栈解析，frames 为空；不新增旧解析开关或双轨路径。已持久化的结构化帧保持有效，不迁移、不删除，Collector 接收与 CLI 符号化能力继续保留。绝对端点立即拒绝远程明文 HTTP，相对端点拒绝反斜杠、控制字符及 origin 变化，并按创建时的实际 location.origin 固定为绝对地址；fetch 与 Beacon 共用该地址，不受初始化前或之后的跨源 base 标签影响。相对端点沿用页面协议，缺失或 opaque origin 时须使用绝对端点。没有持久化兼容窗口；回退以独立差异为边界，不恢复不安全采集作为常规方案。

隐私回归检查不触发 message/stack getter，保留安全 type/code/message 与 trace/span 上下文，并在真实 Node 子进程覆盖原始空 name、带空格 name、旧 message 缩短等无法靠文本区分的反例。原栈位置与帧裁剪用例按用户确认的新契约迁移，保留代码/上下文、体积、去重与过滤器不可变断言；Collector 和 CLI 的结构化帧测试保持原样。调度回归检查批次预算、实例冷却、结果分类和 close 清理。浏览器回归覆盖混合自动捕获开关的同范围实例，并在开发/生产 Chromium 中覆盖初始化前跨源 base、初始化后修改 base、修改 base 后 Beacon 补发；端点用例的全部网络请求均在测试内存中拦截。架构门禁回归使用独立的允许/禁止依赖矩阵。

架构检查使用仓库固定版本 TypeScript 7 实际导出的异步语法树接口，在内存中创建无模块解析、无标准库的检查工程，完成后释放快照与解析进程。单测入口增加 `scripts/__test__` 匹配，保留全部既有测试和 packages 覆盖率范围与门禁。

完成相关检查后执行 lint、typecheck、build、test，按配置范围记录覆盖率；进行全新上下文只读审查并处理有效发现。真实外部服务、部署和发布不属于本次范围。

## TDD 证据

以下失败均来自修复前真实执行的断言，不把参数解析失败或局部覆盖率不足当作缺陷复现：

| 缺陷                  | 修复前失败用例                          | 修复后的行为验证                                                                                            |
| --------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Error 消息隐私        | 6 个 SDK 回归、1 个 PostgreSQL 系统回归 | 不读取 message/stack getter，空或非标准旧 name、旧消息缩短等反例不泄露；安全错误标识与 trace/span 关联保留  |
| 端点明文或跨源泄露    | 9 个配置回归、6 次 Chromium 回归        | 拒绝远程 HTTP 和相对端点跨源；相对地址固定到实际页面 origin，初始化前/后的 base 及 Beacon 均不能改变目标    |
| trace 冷却丢失        | 2 个批次终止回归                        | 尝试耗尽和预算不足两种情况下，后续批次、新 span、重叠 flush 均等待完整冷却且不换端点                        |
| 墙钟回拨              | 5 个 SDK 回归                           | flush、close、自动发送、重试预算和 Error 去重均按单调经过时间工作                                           |
| Beacon 与错误开关耦合 | 3 个浏览器生命周期回归                  | pagehide、visibilitychange、混合开关实例及关闭恢复保持正确接收者，关闭后无补发或遗留定时器                  |
| 多值 traceparent      | 3 个传播回归                            | Headers 合并、逗号文本和大小写重复键均拒绝；数组多值及合法单值未来版本同时验证                              |
| 架构门禁漏检          | 12 个依赖边界回归                       | 19 个 CLI 用例覆盖实际包名、自定义 manifest 名、包子路径、类型/动态/副作用导入、require、相对路径和正向边界 |

共 41 个 Vitest 回归及 6 次浏览器回归取得修复前失败证据。新增 Vitest 用例共 57 个，其中 SDK 37 个、架构脚本 19 个、系统链路 1 个；新增 3 个浏览器场景在开发和生产分别执行，共 6 项。正向契约用例无需先失败。最终 SDK 与架构定向验证为 5 文件、180 项通过。

独立结构与行为审查后的补审确认严格隐私仍保留安全字段，并发现 base 标签会改变相对端点目标。修复前 6 项真实浏览器回归均因跨源目标失败；修复后全部通过，原发现者从当前源码即时构建的独立 Chromium 探针也确认三种场景均固定到页面 origin，定向复核无新发现。
