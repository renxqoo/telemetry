# 同类产品对照与 SDK 采集控制实施记录

日期：2026-11-01。官方来源、现有能力和后续缺口见 [产品对照](../PRODUCT-COMPARISON.md)。

## 交付范围

实现 SDK `eventFilter` 与分类 0 采样，公开只读 `CaptureEvent` 类型并从 browser/server/next 入口导出。过滤只决定接受或拒绝，基于已有安全规范化与白名单，不接收原始 Error 或 SDK 私有配置；重试和 Beacon 复用接受的快照。同步更新 README、SDK 文档和 API 契约。

影响公共导出、SDK 配置、队列/采集生命周期及测试。HTTP/DTO、持久化、数据库模式、服务配置、异步任务和前端入口没有改动。原有大于 0 的采样配置继续有效；0 仅在 SDK 本地丢弃，不把 0 写入协议。回退到不支持这些选项的 SDK 时移除 eventFilter 并恢复其支持的非零采样配置，无数据迁移或兼容双轨。

新增 31 项用例：25 项过滤/采样单测、5 项 ACK 契约单测、1 项真实 HTTP/PostgreSQL/Query API 集成用例。ACK 用例覆盖合法结构且数量相同的重复 ID、错环境/服务、首次项目身份绑定，以及合法乱序/重复确认状态。

## 失败证据与独立审查

新增功能用例在实现前运行 23 项，18 项因缺失过滤和 0 采样能力失败，5 项无效比例边界用例通过；实现后通过。旧配置测试原本断言 0 抛错，依据本次明确的 [0, 1] 目标更新为负数拒绝，没有降低验证标准。

独立只读审查发现新过滤器通过成员调用意外把私有 Configuration 绑定到普通函数的 this。通过公开 createServerClient 增加症状回归，取得修复前失败证据；改为局部函数独立调用并声明 this:void 后通过。审查复核修正与后续 Beacon、真实数据库测试，无剩余阻断发现。未把自查当作独立审查。
