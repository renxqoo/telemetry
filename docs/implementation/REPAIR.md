# 审查修复与验证记录

本轮处理已确认的 HA 准入、项目身份、保留期、CLI 端点切换与文档准确性问题。影响协议 schema、SDK 配置与确认响应、应用配置、PostgreSQL 连接生命周期、CLI 和对应测试；不改变事件持久化格式、数据库结构、权限或同步确认要求。

## 目标行为

- 已运行实例保留失联物理节点的未决连接预算，在健康主库上继续读写。启动仍核对全部配置节点；运行时按节点核对未决连接，不把单节点失联扩大为全实例准入失败。
- 同一实例合并并发主库发现。每个请求保留自己的取消和等待截止，单个等待者取消不能中断其他等待者。主库发现与后端清理共同遵守每节点清理连接上限，关闭时清理在途发现。
- 项目 UUID 在应用配置、SDK 预期项目和 ACK 中采用同一格式规则，支持配置允许的 UUID 版本；事件 ID 和请求 ID 继续采用小写 UUID v4。
- 事件、收据和审计保留天数均在加载与热更新时校验为 1–3660。无效更新保留旧配置，不把配置错误暴露为可重试存储故障。
- CLI 对网络故障和 HTTP 5xx 有界轮换显式配置的端点，429 和其他客户端错误停止；未读取的错误响应体被取消。
- README 与设计文档描述现有实现和真实验收边界，不将单机验证当作生产高可用或容量验收。

## 实施与验证

先添加症状回归并记录修复前失败，再实施对应修复。HA 复用现有三节点 TLS PostgreSQL 探针与真实库测试资产；配置和 ACK 通过公开 SDK/HTTP 路径验证，CLI 通过命令入口验证。

内部实现直接切换，不保留旧准入路径或参数别名；没有持久化迁移或兼容窗口。按实例滚动替换是部署回滚边界，部署不在本轮授权范围内。未决后端预算、同步 COMMIT、RLS 和审计屏障不得降级。

完成后执行 lint、typecheck、build、test 四项门禁与独立只读审查，并记录实际用例数和 packages 覆盖率。容量复测采用现有基线；真实三区故障、fencing、备份还原和 30 天 SLO 需要实际环境，未执行时保持未验收状态。

## 回归证据

配置、项目 ACK 与 CLI 的 12 个新增症状回归在修复前均失败，修复后均通过。项目回归通过 SDK→Collector→存储端口验证 UUID v7、显式预期身份和原配置允许的大写格式；保留期同时验证初始拒绝及更新失败保留原配置；CLI 验证 500/502/503/504 的端点切换、错误流取消和整轮耗尽。

真实三节点 TLS 探针先复现四个并发写入中的第四个失败，再确认共享发现后全部成功。故障代理在第二条数据连接取得身份前阻断握手，随后关闭原主、提升已追平副本并建立新的同步拓扑；修复前恢复实例无法重放确认，修复后已存在与新增事件均确认，原节点两笔债务仍保留。额外覆盖等待者取消、发现期间关闭，以及启动扫描已发现前驱会话但后续节点受阻时关闭。最后一项在接管修复前遗留后端为 1，修复后为 0；全部 9 项 TLS 检查通过。

发现取消与 identity/client.end 交错导致未处理拒绝的精确微时序未取得稳定的修复前动态反例；以当前 pg 代码、独立调用链审查及发现期间关闭的真实网络回归核实。等待辅助函数在所有出口观察已启动的 Promise，发现阶段的身份与 recovery 查询受截止及取消保护。最初代理活动 socket 断言失败来自夹具未消费已收到的握手数据，夹具改为缓存并转发握手后通过，不计为生产缺陷的红证据。

完整门禁首次为 182/183，通过独立 PostgreSQL 同步确认探针定位到配置重载竞态：pg_reload_conf 返回时写连接尚未采用目标设置。夹具先在写连接确认 synchronous_standby_names，再执行原有 SyncRep、超时、取消 WARNING 与本地提交断言；全部断言保留。复跑 183/183 与开发/生产浏览器 4/4 通过。生命周期补充后的最终版本再次完整执行四项门禁，结果见下表。

Next 隐私回归使用各输入独有的敏感标记，避免把 /private/tmp 的正常栈文件名误当正文泄漏；关闭截止回归同时核对调用前后时间窗口中的 100ms 预算，避免毫秒边界误判。
