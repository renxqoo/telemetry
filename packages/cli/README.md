# Telemetry CLI

Run `bun packages/cli/src/main.ts` with one of these commands:

- `events list --environment production` or `errors list --environment production`, with HTTP exact filters as `--from`, `--to`, `--source`, `--service`, `--release`, `--request_id`, and the endpoint-specific `--name`, `--trace_id`, `--user_id` or `--code`, `--fingerprint`.
- `events get --environment production --service web --source server --id <uuid>` or `errors get` with the same identity dimensions.
- `export --environment production --from <UTC-ms> --to <UTC-ms> --out /absolute/output.ndjson [--kind events|errors]`, with the same filters. Both the output and `<output>.manifest.json` are created exclusively with mode 0600. A partial export writes `complete: false` and exits 3; a complete traversal exits 0. The manifest states `live-pagination`, the received-time range, filter digest, count, and separate-snapshot/late-commit/retention limitations. It does not claim a strict point-in-time inventory.
- `doctor` calls authenticated `GET /v1/doctor` and prints CLI/API version and current project, environment, service and permission scope. This endpoint requires a valid service token and does not return credentials.
- `symbolicate --input /absolute/error.json --build-dir /absolute/build` performs local source mapping and needs no token.

Credentials come from injected `TELEMETRY_TOKEN` and comma-separated `TELEMETRY_ENDPOINTS`, or `--credentials /absolute/credentials.json` / `TELEMETRY_CREDENTIALS_FILE`. Credential files must be regular files owned by the current user with mode exactly 0600, containing `{ "token": "key_id.secret", "endpoints": ["https://telemetry.example"] }`. Injected fields override the corresponding file fields. Secrets cannot be passed as command parameters. HTTP is accepted only for loopback development endpoints; embedded URL credentials, query strings, fragments, non-root paths and redirects are rejected. Connection failures and HTTP 5xx rotate through the explicitly configured endpoints for at most one round. Unread error bodies are cancelled; HTTP 429 and other client errors do not rotate. At most eight controlled endpoints are accepted. Each attempt is bounded to 5 seconds and each JSON response to 8 MiB. Runtime failure exits 1, invalid arguments exit 2.

A local build directory contains `.telemetry-build.json` with `{ "service": "web", "release": "v1", "build_id": "build-a", "files": { "/app.js": "app.js.map" } }`. All three identity fields must exactly match the input event. Manifest entries are relative paths without empty, `.` or `..` components or backslashes. The build directory, manifest, map files and entry directory components must not be symlinks. The manifest is at most 1 MiB and each map at most 16 MiB; only regular files are accepted. The reader pins the selected build directory and each directory component, then validates and reads each artifact from one file descriptor. Concurrent path replacements cannot redirect reads outside the selected build directory. No network source maps are fetched.

Secure artifact reading supports Node 26 on Linux and macOS. Each symbolication uses one isolated instance of the current runtime with a 10-second total deadline; termination closes its handles, and the calling process keeps its working directory. Maps are read one at a time and shared frames use one parse per map. Frames with unknown line/column or no explicit map retain their original position. Protocol/source-map coordinates are line 1 and column 0, as verified with a hand-calculated mapping sample.

`runCli(argv, overrides?)` returns an exit status and accepts `stdout`, `stderr`, `env`, and `fetch` overrides. `symbolicateEvent(event, buildDirectory)` returns a cloned event with resolved local positions. These are the public test and embedding boundaries.

Trace commands require `read:traces`:

- `traces list --environment production` requests `/v1/spans`; each item is a span, not a trace aggregate. Exact filters are `service`, `trace_id`, `span_id`, `name`, `status_code`, `min_duration_ns`, `max_duration_ns`, plus `from`, `to`, `limit`, `cursor`.
- `traces get --environment production --id <32-hex-trace-id>` requests the authorized fragment of a trace. It accepts `service`, `from`, `to`, `limit`, `cursor` and returns `completeness: "unknown"`.
- Both support `--format json|ndjson`. JSON returns one page; NDJSON follows signed cursors even across short byte-limited pages. `get --format ndjson --out /absolute/trace.ndjson` creates a new file exclusively with mode 0600, writes incrementally, syncs and closes it. Traversal failure exits 3 and prints `complete:false`; full traversal exits 0 and prints `complete:true` to stderr. It does not buffer the whole trace or claim a cross-page snapshot.

Trace default range is the last 24 hours, maximum 7 days, filtered by received time with an exclusive upper bound. Supply explicit bounds for older traces or a recently committed span at the current millisecond. Responses are bounded to 8 MiB; invalid pages or non-advancing pagination fail. Trace credentials use the same protected inputs as event commands. Event list additionally accepts `span_id` with a valid `trace_id`.
